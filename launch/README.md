## Suggested launch sequence

1. Run the repository checks and review the recorded behavior results. Try one real analysis in the host your audience uses; record its model/version and limitations.
2. Create the `v0.1.0` tag/release at the reviewed commit using the release draft. No release/tag is created by these files.
3. Produce the storyboard, or share the linked written example while the video is pending.
4. Share one relevant demonstration in a community whose rules allow it. Disclose that you made the project, answer feedback, and revise inaccurate claims.
5. Contact a maintainer individually only when you have a specific, useful example to discuss. Do not mass-message.
